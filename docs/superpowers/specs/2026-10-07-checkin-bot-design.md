# Бот отметки посещения пар — дизайн

Дата: 2026-10-07

## Задача

Бот живёт в общей беседе учебной группы. Админ запускает из личных сообщений
текущую пару, бот публикует в беседу сообщение с инлайн-кнопкой «Отметиться».
Нажатие ставит «+» в Google-таблице посещаемости по этому предмету — в столбце
сегодняшней даты, в строке этого студента. Пара закрывается автоматически по
времени окончания.

Критерий успеха: студент в один тап отмечается в беседе, админ не ведёт
таблицу руками, к концу пары в таблице лежат корректные «+», а админ видит,
кто не отметился.

## Границы

В объёме:

- одна учебная группа, одна беседа, одна Google-таблица;
- запуск пары админом вручную, закрытие по расписанию концов пар;
- предметы выбираются кнопками из фиксированного справочника.

Вне объёма:

- несколько групп/бесед;
- расписание самих пар (какая пара по счёту идёт) — бот выводит номер пары из
  времени окончания, а не из сетки звонков;
- редактирование таблицы задним числом, отмена отметки, опоздания;
- админ-панель со статистикой.

## Компоненты

```

services/schedule.py  номер пары и время окончания по времени суток
services/students.py  tg_id → ФИО
services/session.py   активная пара: старт, буфер отметок, закрытие
handlers/admin.py     ЛС админа: запуск пары
```

Модули общаются через явные интерфейсы: `sheets` не знает про Telegram,
`session` не знает про gspread (получает объект-репозиторий), `handlers`
не знают про устройство таблицы.

## Конфигурация

Переменные окружения (`.env`, `env_file` в docker-compose):

| Переменная | Обязательна | Пример | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | `123:ABC` | токен от @BotFather |
| `ADMIN_IDS` | да | `111,222` | TG id админов через запятую |
| `CHAT_ID` | да | `-1001234567890` | беседа группы |
| `PAIR_END_TIMES` | да | `10:05,11:40,13:15,14:50` | времена концов пар по порядку |
| `SPREADSHEET_ID` | да | `1AbC…` | id таблицы посещаемости |
| `GOOGLE_CREDENTIALS_PATH` | да | `credentials.json` | путь к JSON-ключу SA |
| `TZ` | нет | `Asia/Vladivostok` | таймзона учебного заведения, по умолчанию `Asia/Vladivostok` |
| `STUDENTS_PATH` | нет | `data/students.json` | справочник студентов |
| `SUBJECTS_PATH` | нет | `data/subjects.json` | справочник предметов |
| `STATE_PATH` | нет | `data/state.json` | файл рантайм-состояния |

`core/config.py` при старте падает с внятной ошибкой, если обязательная
переменная пуста или `PAIR_END_TIMES` не парсится, а также если пути к
справочникам не существуют или содержат невалидный JSON.

Ключ сервисного аккаунта: файл `credentials.json` в корне проекта, добавлен
в `.gitignore`, в docker-compose монтируется volume.

## Доступ к Google Sheets

gspread + сервисный аккаунт (`gspread.service_account(filename=...)`) —
стандартный headless-путь для серверов: без интерактивного логина и
переустановки чего-либо при правках бота.

Требуется: включить Sheets API и Drive API в Cloud-проекте, создать
сервисный аккаунт, скачать JSON-ключ, расшарить таблицу на `client_email`
аккаунта с правами Editor. Ошибка `SpreadsheetNotFound` почти всегда означает
нерасшаренную таблицу, а не проблему кода — сообщение об ошибке должно это
проговаривать.

Запросы батчатся: один `batch_update` на пачку отметок, а не запрос на
нажатие. Лимит — порядка 60 запросов на запись в минуту на пользователя,
поэтому при всплеске нужен буфер. На HTTP 429 — повтор с экспоненциальной
задержкой (1s, 2s, 4s), до трёх попыток.

### Структура листа

Одна таблица, вкладка на предмет. Имя вкладки берётся из `subjects.json`.

Реальная таблица группы выглядит так:

```
      A     B                    C            D            E
1     №     ФИО                  07.10.2026   09.10.2026   14.10.2026
2     1     Иванов Иван Иванович  +                          +
3     2     Петров Пётр Петрович  +            +            +
```

- колонка с ФИО ищется **по заголовку** «ФИО» в первой строке (регистр и «ё» не
  важны); если такого заголовка нет, берётся колонка A. Так поддерживаются обе
  раскладки: со служебной колонкой «№» слева и без неё;
- строки 2+ — студенты;
- первая строка правее служебных колонок — даты занятий;
- дата ищется сравнением разобранных дат, поддерживаются форматы `DD.MM.YYYY`
  и `DD.MM` (год подставляется текущий);
- если столбца с сегодняшней датой нет — бот создаёт его справа от последнего
  заполненного столбца шапки и пишет дату в формате `DD.MM.YYYY`;
- значение отметки — литерал `+`.

### Интерфейс `services/sheets.py`

```python
class SubjectSheet(Protocol):
    def student_rows(self) -> dict[str, int]: ...      # нормализованное ФИО → № строки
    def ensure_date_column(self, day: date) -> int: ... # № столбца, создаёт при отсутствии
    def is_marked(self, row: int, col: int) -> bool: ...
    def write_marks(self, marks: list[tuple[int, int]]) -> None: ...  # батч
```

Класс `GspreadSubjectSheet` — боевая реализация; в тестах используется
фейк-реализация того же протокола. Нормализация ФИО — `strip`, схлопывание
внутренних пробелов, приведение к нижнему регистру, `ё`→`е`.

## Расписание

`services/schedule.py` — чистые функции без побочных эффектов:

```python
def current_pair_end(now: datetime, pair_end_times: list[time]) -> datetime | None
```

Возвращает ближайшее время окончания, которое ещё не наступило (сегодня, в
настроенной таймзоне). Если все времена на сегодня прошли — `None`, админ
получает «учебный день закончился». Номер пары — позиция найденного времени в
списке, считая с единицы; он используется только в тексте сообщения.

Пример: времена `10:05, 11:40, 13:15`, сейчас `11:00` → конец `11:40`, пара 2.
Сейчас `12:30` → конец `13:15`, пара 3.

## Состояние активной пары

`data/state.json` (на volume, вне git) переживает рестарт контейнера:

```json
{
  "subject": "Матан",
  "sheet": "Матан",
  "chat_id": -1001234567890,
  "message_id": 42,
  "date": "2026-10-07",
  "pair_no": 3,
  "end_at": "2026-10-07T13:15:00+03:00",
  "marked_ids": [111, 222],
  "marks": [[5, 4]]
}
```

`services/session.py` при старте бота читает файл: если `end_at` в будущем —
восстанавливает активную пару (таймер закрытия пересчитывается, кнопка
работает), иначе закрывает её как обычно и очищает файл.

Запись в файл — атомарная (temp + `os.replace`), после каждого изменения
состояния.

## Поток отметки

1. Админ пишет боту в ЛС `/start`. Не админ — игнор с записью в лог.
2. Бот отвечает клавиатурой предметов из `subjects.json`.
3. Админ жмёт предмет. Бот:
   - определяет время окончания через `schedule`; `None` → «учебный день
     закончился», выход;
   - если активная пара есть — закрывает её (как в разделе ниже);
   - читает вкладку предмета, находит/создаёт столбец сегодняшней даты,
     строит карту ФИО → строка, читает уже стоящие «+» в этом столбце;
   - постит в `CHAT_ID`: `📚 Сейчас идёт: Матан (3 пара, до 13:15)` и кнопку
     «Отметиться» с `callback_data = att:<message_id>`; id сообщения играет
     роль идентификатора сессии, по нему кнопка отличает свою пару от чужой;
   - сохраняет состояние.
4. Студент жмёт кнопку:
   - активной пары нет, или `callback_data` не совпадает с текущей, или
     время окончания прошло → «пара закончилась»;
   - `tg_id` нет в `students.json` → «тебя нет в списке группы»;
   - ФИО нет в листе → ответ «не нашёл тебя в таблице», админу уходит
     уведомление с ФИО;
   - уже отмечен (в `marked_ids` или в клетке стоит `+`) → «ты уже отмечен»;
   - иначе — пометка в буфер, в `marked_ids`, ответ «отмечен ✅». Ответ
     мгновенный, запись в таблицу асинхронная.
5. Буфер сбрасывается по таймеру (~2 сек тишины) или при накоплении 20
   отметок. Ошибка записи после трёх попыток — админу в ЛС уходит сообщение
   с перечнем не записавшихся, отметки остаются в буфере для следующей
   попытки.

Повторное нажатие идемпотентно: второго «+» не появляется.

## Закрытие пары

В момент `end_at` бот:

1. дописывает буфер (`write_marks`), при ошибке — повторяет и уведомляет
   админа;
2. правит сообщение в беседе: `Матан — пара закрыта, отметились 12 из 25`,
   инлайн-клавиатура убирается;
3. шлёт админу в ЛС отчёт: отметившиеся и не отметившиеся по справочнику
   группы (только те ФИО, что нашлись в листе);
4. очищает состояние и `data/state.json`.

Закрытие выполняет asyncio-задача, запущенная при старте пары; при
восстановлении из `state.json` — с пересчитанной задержкой. Одновременно
активна не более одной пары: старт новой закрывает предыдущую.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| `SpreadsheetNotFound`, нет вкладки, нет доступа | лог + сообщение админу в ЛС, пара не стартует |
| HTTP 429 / 5xx при записи | backoff 1s/2s/4s, затем уведомление админу |
| ФИО студента нет в листе | плюс не ставим, уведомление админу |
| Бот не может править сообщение в беседе | лог, отчёт админу всё равно уходит |
| Битый `state.json` | лог, файл игнорируется, состояние пустое |
| Не-админ пишет в ЛС | игнор, запись в лог |
| Нажатие не из `CHAT_ID` | игнор |

## Тестирование

pytest, TDD — тесты пишутся до реализации.

Юнит-тесты (без сети):

- `schedule.current_pair_end` — все границы: до первого конца, ровно в момент
  конца, между парами, после последнего, пустой список;
- `students` — загрузка, поиск по id, нормализация ФИО (`ё`, регистр,
  лишние пробелы);
- `session` — старт пары, идемпотентная отметка, буферизация и сброс,
  закрытие, восстановление из `state.json`, старт новой пары поверх активной;
- `sheets` — на фейковом gspread-клиенте: поиск существующего столбца даты,
  создание нового, чтение карты студентов, батч-запись;
- `config` — валидация обязательных переменных и парсинг `PAIR_END_TIMES`.

Ручная проверка: тестовая таблица + тестовый бот-токен, прогон сценария
«админ запустил пару → студент отметился → наступил конец пары».
